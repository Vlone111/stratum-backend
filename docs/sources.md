# Регламент подключения источника

Оператор согласует с владельцем источника рабочее пространство, формат, устойчивый идентификатор измерения, единицы, период поступления и доступ к данным. При интеграции используются канонические названия полей из таблицы ниже. Поставщик с другой схемой может подготовить экспорт или совместимое представление БД.

| Поле | Правило |
| --- | --- |
| event_id | Строка от 1 до 100 символов. Допустимы буквы, цифры, подчёркивание, точка, двоеточие и дефис. Идентификатор стабилен в пределах одного источника |
| revision | Положительное целое от 1 до 999999999. По умолчанию 1. Исправление принятой версии получает больший номер |
| station | Идентификатор поста, те же правила, что у event_id |
| metric | `pm10`, `pm2_5` или `noise` |
| observed_at | ISO 8601 с часовым поясом, например `2026-10-14T08:00:00+05:00` |
| value | Конечное число или десятичная строка с точкой, модуль до 10¹² во входной единице. Концентрация должна быть неотрицательной |
| unit | Для частиц принимаются `mg/m3`, `ug/m3`, `µg/m³`. Результат в µg/m³. Для шума принимается `dBA` |
| seq | Только для SQLite и REST. Строго возрастающий положительный целый номер строки до 2⁶³−1. Исправление старого события приходит новой строкой с новым seq |

### Подготовка привязки

Для CSV, SQLite и REST оператор создаёт `$STRATUM_DATA/bindings.json` по [образцу](../examples/bindings.json). Верхний ключ совпадает с workspace. В каталоге указываются абсолютные пути, доступные процессу обработчика. Оба процесса должны видеть одну и ту же версию файла. В Compose можно скопировать файл привязок через `docker compose cp bindings.json api:/data/bindings.json`, а исходные файлы положить по путям, указанным в нём, на том же томе. Опубликуйте обновление каталога атомарной заменой файла. Для REST с авторизацией задайте переменную из `token_env` в окружении worker. Реальные адреса с токенами и пароли не включайте в каталог фронтенда.

Редактор получает имена привязок через `GET /v1/bindings` и создаёт поток, например таким телом для `POST /v1/sources`.

```json
{"name":"Лаборатория, северная площадка","kind":"csv","binding":"lab-export","interval_seconds":300}
```

Период — от 10 до 604800 секунд. При пропуске поля ручной запуск остаётся доступен. Для проверки выполните `POST /v1/sources/{sid}/runs`, откройте карточку задания и сверьте число строк, первую дату, единицу и контрольное значение. После приёмки включите период через `PATCH /v1/sources/{sid}`.

### CSV

Сервис перечитывает один UTF-8 файл с заголовком и разделителем-запятой. Допустим BOM. Лимит снимка — 5000 строк и 2 МиБ. [Демонстрационный файл](../examples/laboratory.csv) содержит исправление, повтор и ошибку. Поставщик записывает временный файл, затем атомарно заменяет опубликованный снимок. Чтобы сохранить промежуточные версии, держите их в снимке до подтверждения загрузки. При неверном заголовке или разрыве структуры CSV задание целиком повторяется. При неверном значении в корректно прочитанной строке в карантин попадает только эта строка.

### SQLite

Обработчик открывает зарегистрированный файл в режиме `mode=ro` и читает таблицу или представление `readings`. Для нового архива подойдёт следующая структура.

```sql
CREATE TABLE readings (
  seq INTEGER PRIMARY KEY AUTOINCREMENT,
  event_id TEXT NOT NULL,
  revision INTEGER NOT NULL DEFAULT 1,
  station TEXT NOT NULL,
  metric TEXT NOT NULL,
  observed_at TEXT NOT NULL,
  value REAL NOT NULL,
  unit TEXT NOT NULL
);
```

Каждая новая строка имеет `seq` больше предыдущего курсора. Обработчик запрашивает страницы по 250 строк в порядке возрастания. Для исправления добавьте строку с тем же event_id и большей revision. Изменение строки на месте за уже пройденным курсором останется невидимым.

### Внешний REST API

Адаптер выполняет `GET <зарегистрированный URL>?after=0&limit=250`. Поставщик возвращает JSON со следующей структурой.

```json
{
  "items": [
    {"seq":12,"event_id":"network-12","revision":1,"station":"west","metric":"pm10","value":19,"unit":"ug/m3","observed_at":"2026-10-14T03:00:00Z"}
  ],
  "has_more":false
}
```

Ответ ограничен 2 МиБ. Требуются уникальные возрастающие seq строго больше `after`. `has_more=true` требует хотя бы одну строку. Система сохраняет последний seq и ставит продолжение в очередь в одной транзакции. Пустая страница с `has_more=false` завершает опрос. Тайм-аут сетевого чтения — 5 секунд. Для реального поставщика с токеном используйте HTTPS. В локальном демо тот же адаптер вызывает HTTP-сервис на loopback.

### Webhook от веб-сервиса

1. Создайте источник телом `{"name":"Передвижной пост","kind":"webhook"}`.
2. Выполните `POST /v1/sources/{sid}/key` от имени редактора и передайте ключ системе-отправителю. Повторный выпуск отзывает предыдущий ключ.
3. Отправьте пакет от 1 до 500 элементов с заголовком `X-Source-Key`. Лимит всего HTTP-тела — 1 МиБ. Переменные ниже обозначают ID источника и выданный ему ключ.

```sh
curl -i "http://127.0.0.1:8000/v1/hooks/$SOURCE_ID" \
  -H "X-Source-Key: $SOURCE_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @examples/webhook.json
```

HTTP 202 с `job_id` подтверждает сохранение исходного пакета в очереди. Результат обработки смотрите в журнале под пользовательской сессией. Если подтверждение потеряно, повторите отправку с прежними event_id и revision. Для исправления принятой версии увеличьте revision. Для исправления строки из карантина, у которой ещё нет принятой версии, можно сохранить исходный номер.

### Приёмка подключения

Сверьте число строк у поставщика со счётчиками завершённых заданий каждой страницы. Затем повторите тот же набор и сверьте число актуальных измерений. Проверьте намеренно ошибочное значение, исправление с большей ревизией и отсутствие результатов в другом рабочем пространстве. Зафиксируйте объём пакета, ожидаемый период и допустимую задержку. Численные требования к задержке и реальный перечень источников согласуются с заказчиком.
