# Сценарий работы и демонстрации

В роли инженера откройте рабочее пространство `ural` по [инструкции запуска](../README.md). Все действия доступны в Swagger UI до готовности панели. Данные относятся к 14 октября 2026 года, поэтому при фильтрации по дате выберите этот день.

1. **Проверьте поступления.** В обзоре нового стенда семь актуальных измерений. В журнале четыре стартовые загрузки. Откройте запись `partial` для источника «Протоколы лаборатории». Система получила пять строк, сохранила три версии, узнала один повтор и поместила одну строку в карантин.
2. **Проверьте показание.** Найдите в измерениях пост `north`, метрику `pm10` и пробу `lab-041`. Панель должна показать **21 µg/m³** на 03:00 UTC. Лаборатория прислала первое значение 0,023 mg/m³, затем уточнила его до 0,021 mg/m³. В истории пробы видны обе версии — 23 и 21 µg/m³. Повтор первой ревизии в конце файла не изменил актуальный результат.
3. **Разберите ошибку.** На экране отклонений откройте строку данных 4 (`lab-043`). В графе значения лаборатория написала «меньше порога». Первоначальная строка и причина сохранены. Сервису требуется численное значение, и он не подставляет ноль.
4. **Исправьте данные.** В локальной копии `.demo/laboratory.csv` замените «меньше порога» на `8`, сохраните файл и запустите загрузку CSV ещё раз. В новом задании ожидаются `received=5`, `applied=1`, `skipped=4`, `rejected=0`. В обзоре теперь восемь измерений. Предыдущая запись карантина остаётся в журнале.
5. **Проверьте повтор.** Запустите тот же файл ещё раз. Ожидаются пять повторов, ноль добавленных версий и восемь актуальных измерений. Для фотографии экрана защиты удобнее всего показать рядом журнал и историю `lab-041`.
6. **Проверьте роли.** Войдите в `ural` под `viewer`, откройте те же результаты и попробуйте запустить загрузку. API вернёт 403. Войдите в `volga` под `editor` и откройте журнал. В новом пространстве он пуст.

## Если источник перестал отвечать

Откройте карточку задания. Ошибка чтения появляется в `error`. Обработчик повторяет загрузку после 2 и 4 секунд ожидания. После третьей неудачи задание переходит в `failed`. Восстановите доступ к источнику и нажмите «Повторить». Новое задание получит собственный идентификатор. Для `partial` исправьте исходную запись и отправьте её снова. Если правите уже сохранённое значение измерения, увеличьте `revision`.

Чтобы проверить этот путь на стенде, временно переименуйте локальный `.demo/laboratory.csv`, запустите ручную загрузку и дождитесь `failed`. Верните прежнее имя файлу и повторите задание. Если журнал долго показывает только `queued`, проверьте, запущен ли процесс `stratum.worker`. В деморежиме его запускает команда `scripts.demo`.
